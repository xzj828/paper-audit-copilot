# PDF 加载、翻页与失败恢复

阅读器加载文件和渲染页面时显示可访问的状态提示。页面渲染失败时隐藏未完成的画布，显示错误与“重试”；翻到其他页会开始一次新的渲染，成功后旧错误不再保留，对照页切换按钮可继续使用。“重试”沿用重新加载当前文件的方式，不修改上传文件或服务端解析。

切换文件时先解除旧文档与对照控件的关联，再异步清理旧任务。清理完成及 PDF.js 模块加载完成后，均检查当前任务是否仍有效；已经被后一次切换取代的任务立即结束。每次加载使用开始时的 URL，避免旧任务在等待期间转而重复加载最新文件。既有渲染序号仍负责拒绝过期页面的成功或失败结果。

## 复现与验证边界

三条组件浏览器控制在 Chromium 中挂载真实生产 PdfReader，加载开发者三页向量 PDF。仅在测试浏览器内通过 PDF.js 公共对象的原型注入一次 getPage 失败、可手动释放的页面延迟及旧 destroy 延迟；生产代码没有测试后门。验证失败后转页和重试、等待提示、旧失败不能覆盖新页、快速缩放/转页，以及 a→b→c 文件切换期间旧控件立即隐藏、最终只请求 a/c 两个文件。

另一条流程从空工作台真实创建项目并上传该 PDF，仅拦截浏览器原文件请求一次返回 HTTP 503；生产服务器照常解析。打开批注页后重试恢复，再搜索 Measurement 的三个原页位置，在第2页显示准确来源框，手机布局检查。完整解析和报告字段前后相同；本控制没有生成评审报告，不据此声称验证了冻结报告不变。

修复前原实现三项控制全部失败；为独立观察旧任务覆盖问题，另一次临时跳过前置“加载中旧控件应消失”断言的调查也失败，最终正式测试保留完整断言。首次修复复跑2项通过、1项因测试错误地将1055.7像素宽写成1055而失败，按612点页面×150%×1.15修正；补充实际上传测试首次因未打开批注页失败，已按真实用户路径修正。所有过程日志哈希保留在 pdf-render-recovery-validation.json。

这些是有限的软件失败与竞态控制，未模拟所有 PDF、设备、网络或 PDF.js 故障，不统计专家准确率、模型质量或用户耗时收益。原文、检索策略、锚点算法和服务端解析不改；完整回归另覆盖原许可 PLOS20页文件的阅读与对照。所有本轮控制均无外部模型调用。

## 复跑

`npx playwright test tests/e2e/pdf-render-recovery.spec.js` 运行四条流程；`npm run check` 执行生产构建、Node 与全部浏览器测试。测试使用 Vite 编译后的生产组件及其实际 Vue/PDF.js 模块，不读取用户材料或浏览器凭据。当前实现指纹、材料指纹和检查记录见同名验证 JSON。
