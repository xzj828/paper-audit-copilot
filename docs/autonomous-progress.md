## 每次自动运行的执行步骤

1. **恢复现场。** 阅读本账本、当前用户指示及最近实际验证记录；检查分支、远端、未提交文件和正在运行的任务。先识别未提交内容属于谁、完成到哪里及是否需要继续验证，保留用户和协作成员的工作，不重置或删除来制造“干净”状态。
2. **核对远端。** 获取 `origin` 主仓库与保留的 `upstream` 协作仓库最新状态，比较本地与远端提交。发现远端 ahead 时，先审阅新提交，再正常整合；纯远端前进可快进，有并行修改则合并或在隔离分支协调。冲突按实际功能解决并验证，不 force push、不覆盖协作者提交。
3. **选择下一项。** 优先处理上表仍可自主完成的 P0 / P1 工作，以及验证发现的实质缺陷。一轮选取 1–3 个边界明确的模块；能并行的只读检查或不同文件任务可有限并发，避免重复占用测试端口或同时操作同一浏览器窗口。
4. **实现与留证。** 在已授权范围内完成代码、实际数据流、界面和材料。记录依赖、来源、权限与预算。真实论文的许可必须实际核对，原文预期必须可追溯；未跑过的实验标为待运行。发现任务依赖专家、私有资料或新权限时，先完成不依赖它的部分并继续其他模块。
5. **验证。** 先运行与变化相关的确定性检查和目标浏览器流程，保留失败原因并修复。拟推送的代码完成后运行适当的完整检查；只有实际通过才登记数量。测试报告区分合成控制、公开真实材料、模型调用及专家标注，不混成同一“准确率”。
6. **分模块推送。** 审阅变更，排除密钥、私人资料、运行数据库、依赖、临时输出和未获许可文件；按功能、测试和文档的实际范围提交到当前 `origin` 主仓库。推送前再核对远端；有协作者新提交则先整合，不改写已有历史。使用现有获授权的 GitHub 推送方式，不提取或输出浏览器凭据。
7. **核对交付。** 读取推送后的远端提交，逐文件比较本轮计划内容与本地最终内容，保留远端提交标识与差异结果。确认远端字节一致后，更新源码包、技术 PDF 和其他用户交付物；PDF 实际编译与逐页检查，压缩包排除敏感及运行文件。
8. **继续下一阶段。** 将本轮结果、遗留失败、阻塞条件和下一项任务追加到本账本。还有已授权且可完成的工作时，直接开始下一项或交由已配置的定时主动检查继续；不把一条完成回复视为整个持续开发目标结束，也不重复请求“继续 push”的授权。
