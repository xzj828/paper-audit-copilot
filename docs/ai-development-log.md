# 本轮 AI 开发与验证记录

## 需求与授权

本轮从仓库 main 的 108a962（v0.2.0）继续开发。用户要求：“请你在这个仓库的基础上，按照比赛要求继续 push”，明确参加传智杯 AI WEB 赛道，并要求“直接把作品做出来”。用户确认本轮范围：完善全文检索问答、可点击证据与覆盖范围，补齐测试和参赛文档，分模块提交后推送到 xzj828/paper-audit-copilot。

比赛要求以参赛者提供的第九届赛道截图为主要材料，并查阅东莞理工学院计算机学院 2026 年 9 月 20 日通知（来源链接见 competition.md）。没有原始资料的历史 Prompt、团队身份与历史工作量不补造。

## 实际改动

- 将对话的固定前 24000 字符上下文改为遍历当前版本全文的分块检索。采用 BM25、中文分词与二元词组、有限中英文科研词表，限制最多 8 块和 12000 字符上下文。
- 来源由服务端建立，携带当前版本、解析任务、段落、页码与原文片段。界面显示检索策略、所选块数、上下文大小与范围声明。
- 增加桌面和手机证据卡片。点击后定位原文关键片段；回答与证据一起持久化，刷新仍可追溯。
- 模型上下文要求使用 [R1] 等引用；未知编号与未标注来源会产生提示。编号检查不等于语义真实性验证。
- 未命中问题明确说明证据不足，并且不调用模型。概览问题均匀抽取全文样本，明确说明覆盖边界。
- 提供评分要求对照、技术说明及 4 页 PDF、约 6 分钟视频演示脚本。队伍实名、正式视频和赛事系统提交仍由参赛团队完成。

## 发现问题及修复证据

1. 自然语言中的“样地”被 Intl.Segmenter 拆成单字，首次新单元测试失败；补充汉字二元词组后通过。
2. 新浏览器测试在项目创建尚未完成时上传，实际仍处于空工作台；等待当前项目标题后再上传。
3. 大段落里的晚段证据出现在卡片截断范围外；增加围绕命中词的原文摘录和定位片段，并滚动到实际高亮标记。
4. 既有浏览器测试仍依赖此前已删除的内置演示项目和旧演示界面。用专属测试数据目录里的合成控制样例替换，调整为当前界面断言。产品仍不自动创建演示项目，新检索测试从真实空工作台开始。
5. 连续 PDF 测试遇到冷启动解析超过原有 10 秒等待；单独验证正常后将该解析等待设为 20 秒。没有更改产品解析结果。

## 后续迭代：多轮追问与研究记录导出（2026-10-07）

用户在上述 8 次模块提交后要求“继续 push”。本轮将可追溯问答推进到可下载的研究记录，并补齐简短追问的主题延续。

- 明确的简短中文追问从当前版本最近三条用户问题中找明确主题，再重新检索原文。记录 queryText 与 followUpTo，界面显示沿用的问题。不用助手生成结论扩展查询；新的明确主题不继承旧查询。
- 增加当前版本 Markdown/JSON 问答导出，保存时间、版本、文件 SHA-256、原文完整切片、检索范围和引用警告。只读取字段清单和指定版本的已保存问答，隔离其他空间与版本，不回退错误版本 ID。
- 导出记录保留原文与当前解析的文字归属检查，文字匹配不表示语义核验。Markdown 将问答、原文和内嵌反引号放入文字块，来源编号只在每条回答内有效。
- 项目菜单增加导出入口，桌面和手机支持下载。更新使用说明、技术文档及 PDF。

新增 5 项 Node 测试，覆盖追问边界、来源快照、原文保真、工作空间及版本隔离；扩展 2 项浏览器流程，检查真实 Markdown/JSON 下载内容、连续追问的来源和手机端引用警告保存。首次新增导出测试误把进度事件索引当作回答索引，修正测试样例索引后通过，产品逻辑不需要为此改动。

最终 `npm run check` 退出 0：生产构建、91 项 Node 测试、23 项浏览器测试通过。随后调整证据范围长词换行并增加手机导出截图，再执行生产构建及这 2 项浏览器测试，均通过。`git diff --check` 通过。更新的技术 PDF 已逐页检查，正文可读、页数符合要求。

本轮仍使用合成控制材料与受控模型服务，不增加专业准确率声明，不替团队录制真实讲解视频或提交赛事系统。

## 智能完善迭代：证据工具与预算（2026-10-07）

用户询问：“你还可以补充一些什么新的功能吗，让他更加完善和智能，我们的目标是全国一等奖”，随后要求“继续”。基于已有代码只读审查，本轮明确新增参考 DOI 核验、CSV 描述统计复算和科学审查预算；既有分项评审、图文阅读、独立模型复核和版本复查不重复列为新增能力。

实际实现：明确书目区段抽取、Crossref/DataCite 精确 DOI 查询、去重和查询范围；严格 CSV 上传／列映射／全表与分组统计／原文均值差异；模型请求前预留预算计数、累计实际运行时间、预算暂停和同任务恢复。工具使用独立版本快照和受保护 JSON 下载，报告复制生成时工具结果并显示冻结附件；模型评审尚未消费工具结果，科学评分不随手动工具改变。

检查与修复记录：

- 跨模块独立审查发现“附录 A／附录A”未停止书目扫描，可能把补充方法 DOI 纳入参考条目；补充结束标题及同页、跨页测试。
- CSV 的异步响应原本只判断项目身份；补充项目、版本、解析身份与请求 generation，切换及卸载中止请求。
- 两类工具并发结束时，迟到的旧 POST 项目快照可能覆盖较新前端记录；改为成功后读取最新存储，浏览器测试真实延迟旧 CSV 响应并确认新参考记录不回滚。
- 已有科学报告时，保存新工具解析报告原本可能仍打开旧 trial 报告；显式选择本次新报告，增加网页冻结快照展示和导出附录。
- 首轮浏览器预算测试的受控服务错误地发送 SSE，而科学评审请求要求非流式 JSON；修正测试服务协议。旧布局断言未计入新增预算摘要行；调整为检查配置／报告按钮对齐，以及预算行与输入区间距。
- 运行环境默认沙箱禁止本机监听端口；完整回归改在获准的本机测试环境运行，不把监听失败当作产品缺陷。

完整 `npm run check` 退出 0：生产构建、116 项 Node 测试、25 项 Playwright 测试全部通过。随后补充手机端直接可见的统计摘要和两工具并发响应回归，最终生产构建与 2 项证据工具浏览器测试再次通过。`git diff --check` 通过。技术说明更新为 5 页 PDF，逐页检查无裁切或文字溢出。

材料为合成 DOCX、已知统计量 CSV、受控注册机构与本机模型服务响应，没有运行付费商业模型或虚构专家准确率。本轮首次完整检查失败及修复如上保留，最终日志保存在本地工作文件中；源码和参赛材料按实际模块推送，不回填日期或虚构开发历史。专业质量下一步仍需要获准使用的真实论文、独立领域专家标注和保留测试集。
