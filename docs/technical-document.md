# 学术审稿 Copilot 技术文档

第九届传智杯 AI WEB 网页开发挑战赛 | 2026-10-24

## 1. 项目概述

本作品是一款面向生态学实证论文的 AI Web 工作台，将文档阅读、检索问答、结构化评审、原文证据和版本修订联结为可追溯流程。作品沿用已有开源协作仓库，在保留真实上传、模型评审和持久化能力的基础上，完善长论文全文检索、主张与证据链、参考 DOI 核验、CSV 复算和审查预算。

参赛交付以浏览器 Web 应用为主体；Electron 桌面版提供补充使用形式。产品首次打开为空空间，用户上传自己的文件。参赛开发仓库由 wilsonwuww 拥有，按用户要求独立为私有仓库；基础来源为 xzj828/paper-audit-copilot，保留原项目署名与完整历史。协作过程通过 GitHub 提交记录核查。参赛队伍实名信息以报名登记为准，本文不推断学校、学生或指导教师姓名。

项目价值在于减少反复搜索原文、整理评审意见和核对修订版本的操作成本。当前尚未完成真实领域专家校准，因此不宣称能够取代同行评审，不给出未经验证的准确率、录用概率或时间收益统计。

## 2. 需求与用户流程

目标用户是需要理解稿件证据和修订要求的学生、作者及科研团队。传统阅读工具与聊天工具分离，模型回答常难以对应具体原文；修改稿与旧意见之间也缺少稳定关联。

- 文档需求：真实 PDF/DOCX 上传、去重、后台解析、失败重试、原文件保存。
- 问答需求：长文档后部可检索，中英文科研术语可查询，答案来源可点击，证据不足时有明确反馈。
- 评审需求：按固定规则执行、逐条问题复核、材料请求单列、任务进度可见。
- 修订需求：旧报告不可被新状态覆盖；新版证据与原问题、修复条件建立关联。
- 使用需求：桌面和手机均能使用，流式反馈、工作空间隔离、密钥不暴露给前端。

核心流程：新建项目 → 上传文件 → 解析完成 → 原文问答或分项评审 → 点击证据 → 保存问题与报告 → 上传修改稿 → 版本比较与复查 → 导出报告。模型问答与科学评审是两个明确流程；聊天不会自动改变评审结论。

## 3. 系统架构

前端使用 Vue 3 Composition API、TypeScript 与 Vite。App 工作台管理项目、论文版本、对话及面板；独立组件负责模型配置、PDF 阅读、管理页、评审控制和检索证据卡片。PDF 页面渲染采用独立 Worker，聊天和文档分别滚动，面板宽度可调整并保存。

后端使用 Node.js 24.12+、Express 和 Node 内置 SQLite。HTTP API 负责匿名工作空间、文件上传、版本和消息；独立解析 Worker 执行 PDF.js 文本坐标提取与 Mammoth DOCX 文本提取。文件以版本 ID 独立保存，数据库保存可序列化的项目、任务和报告快照。

AI 服务分为四个入口：检索问答、版本化科学评审、修订语义复查和可选的主张证据关系判断。兼容模型接口使用 Chat Completions 和 SSE。视觉分析使用真实 PDF 页图及区域裁剪；外部文献比较通过 Crossref/DataCite 元数据快照完成。所有任务通过服务端当前空间与版本的数据执行，不从模型回答生成数据访问路径。

数据链路：浏览器 → 同源 HTTP/SSE → 工作空间与版本 → 文档解析/检索/评审 → 兼容模型服务 → 校验与持久化 → 浏览器原文导航。每一条消息、问题及报告都有自己的时间与版本归属。

## 4. 全文检索增强问答

改动前，问答上下文固定取论文前 24000 字符；后部方法、结果或局限可能未发送。本轮在全部已解析文本上执行词法 RAG，并严格限制送给模型的片段数量与体积。

1. 每个原文区块拆成不超过 1000 字符的片段，保留 120 字符重叠，优先在句末换行断开。片段保存原区块 ID、页/段落、字符偏移和逐字原文。
2. 使用 Unicode NFKC 与小写进行检索标准化；中文词边界由 Intl.Segmenter 提供，并加入双字匹配以处理“样地”等词典拆分。原文引文保留原始排版，不用标准化文本替代来源。
3. 查询去除常用虚词，有限扩展 sample/样本、methods/方法、results/结果等科研术语。ecology-term-map@1另登记光合作用 / photosynthesis与生境破碎化 / habitat fragmentation完整短语；证据卡片展示映射，导出保留版本。扩展是显式词表，不代表通用跨语言语义理解。
4. 以 BM25 的文档频率和片段长度归一化排序，k1=1.2、b=0.75。每次最多选择 8 个来源、12000 字符检索上下文，抑制重叠过大的同区块片段。
5. 选中批注遵循 exact-occurrence@2，明确偏移必须逐字对应该位置，缺少位置的重复引文不能优先第一处。概括类一般问题从全文均匀抽样，展示抽样范围。
6. 检索为空时直接返回证据不足，不调用模型。该状态不表示论文一定没有相关内容；词法检索仍可能漏检同义表达。

本轮未使用向量数据库、嵌入服务或模型重排序，因此检索可离线复现，新增服务成本较低。后续可在专家测试数据集上比较 BM25 与向量混合检索，再决定是否增加外部依赖。

历史 bm25-lexical@2 保留 p、n、r、t、f、α、β、χ 等单独科学符号，并处理“第2组”“表1”的汉字与数字边界。当前 bm25-lexical@3 新增有来源的两条双向术语：完整短语不回退到孤立 fragmentation，不将标题与正文拼成术语；NFKC检索索引映射回原文 UTF-16 后生成摘要。历史消息保存各自策略，原文切片保持不变。否定句仍可词法命中，未登记近义表达仍可能漏检；不保证语义关系正确。词表来源与边界见 retrieval-terminology.md。

多轮问答中，“为什么”“再详细解释”等明确的简短追问，会在当前版本最近三条用户问题中寻找明确主题，再重新检索当前版本原文。界面显示沿用的问题；助手生成的结论不充当检索词，新主题问题不借用旧查询。没有可用历史时仍明确返回证据不足。

## 5. 证据交互与引用控制

检索结果由服务端编号为 R1、R2 等，模型仅获得这些片段及其编号。系统提示要求原文事实引用本次编号，并区分事实、推断及未知；论文和历史对话被当作待分析资料。

SSE 首先发送检索来源和覆盖元数据，再发送模型正文片段。前端在等待期间即可展示检索范围；完成后持久化来源、版本 ID、解析 ID、策略与引用状态，刷新不丢失来源。

证据卡片从原文切片生成，摘要围绕检索命中位置展开，点击跳转到来源页或段落并高亮。模型没有权限生成跳转目标或跨项目检索；旧消息没有新字段时仍可正常显示。

引文策略统一为 exact-occurrence@2：无明确偏移时原文必须唯一；明确偏移须为非负安全整数并逐字对应该位置，不能忽略错位置后选第一处。排版标准化只接受唯一映射，不修补明确错误偏移。主张、CSV、修订和外部比较保留已核验位置；旧 DOCX 歧义引文明确提示，历史记录不自动改写。

PDF 新解析按原有 PDF.js 文字顺序保存每个文字块的 UTF-16 起止偏移、逐字文字与页面视口矩形。点击来源先核对具体页、区块和字符偏移，同页重复文字使用保存的实际出现位置；跨行引用可显示多个文字框。矩形考虑旋转与裁剪，缩放后按比例对应实际页面；手机端提供缩放，连续页纵向排列。位置框覆盖整个文字块，可能包含相邻字，不宣称逐字形精度。旧解析无坐标、旧偏移歧义或引文失配均明确提示，不猜第一处。原文搜索同样按实际命中偏移定位。

v12原文搜索采用source-occurrences@1，逐处显示最多60处匹配，重复文字分别携带实际字符偏移。多词查询兼容ASCII空格与单次LF/CRLF差异，界面标注兼容匹配；原文引文、解析文本与位置框不改写。不跨区块、页、TAB单元格或空行拼接，不移除断词连字符。该策略仅用于手动原文搜索，不声称BM25问答或模型语义能力提高。详见source-search.md。

v15另提供默认关闭的pdf-hyphen-candidates@1手动搜索：兼容ASCII字母间的行末连字符，候选仍保留原始连字符、换行和偏移，列表及阅读器明确提示人工核对。两侧原始字母、单次换行、200字符查询及60处结果有界；不跨页或区块，不适用于DOCX，不改变BM25、评审或解析。真正复合词也可能进入候选，不能据此宣称词义或拼写正确。详见hyphen-candidates.md。

v16阅读器增加默认关闭的相邻页人工对照：选择上一页或下一页，桌面并排、手机上下排列，保留实际页码与原比例滚动。对照只额外立即渲染一页，开启期间暂时替代连续阅读，关闭恢复原布局；首尾页限制、缩放、刷新及版本切换均保持明确。证据框只在当前页，不把相邻页拼成引文或自动重建跨页表格。详见pdf-comparison.md。

v17增加相邻页一键切换，工作台及文献预览在同一对页面间交换当前页与对照页，方向随之反转。工作台清除旧引文、视觉框和搜索状态，避免相同表头继承旧高亮；原页文字和证据不拼接，不自动识别续表。详见pdf-page-swap.md。

v18完善PDF异步加载与失败恢复：新页开始渲染时清除旧错误、显示加载状态；切换文件时立即解除旧文档，清理与模块加载后检查任务归属，防止旧任务重复加载或移除新文档。重试沿用重新加载当前文件，原文及服务端解析不改。详见pdf-render-recovery.md。

PDF 位置映射不重建双栏阅读顺序、跨页表格、图像或完整公式。竖排、裁剪区域外和退化坐标不获得误导性位置框；解析与界面继续显示覆盖限制。已保存的旧报告和解析不自动改写。

PDF逐页解析体检另保存pdf-extraction-diagnostics@2：每物理页的字符、非空白UTF-16字符与可定位非空白文字块数量。界面显示无文字、少于30字符和坐标缺口的页，支持筛选、手机刷新及点击原页；该导航清除旧高亮，不生成证据。JSON下载保留文件SHA-256、版本和解析身份，新报告冻结体检，Markdown/DOCX/PDF均保留独立附录。科学评审请求只接收汇总、前40个待核对页与明确遗漏数量，不自动改变评分。旧解析显示未记录；有文字和坐标不代表图表已理解，短页也不能认定扫描件。详见pdf-inspection.md。新增pdf-parallel-regions@1有限并列区与跨区切换提示，仅在完整坐标上统计水平几何；表格和列表也可触发，不能判定抽取错误。界面、JSON和报告保留候选块、对齐行及切换次数，原文未重排，v1历史字段不补造。模型仍只接收前40个待核对页及遗漏数，详见pdf-layout.md。

DOCX 新解析器保留表格行列、横纵合并和加粗、斜体、上下标等有限格式。表格按实际单元格用 TAB/LF 规范化为检索文本，位置基于该文本的 UTF-16 字符偏移，不是 Word 页码或 ZIP 字节。点击引文跨多个单元格时分别高亮实际文字；来源摘要另存起点，重复数字不会因为忽略偏移而落到另一处。手机端表格可在独立区域横向滚动。旧解析与报告不自动重写。

DOCX 中间 HTML 只在后端提取文字与有限结构，不直接进入页面；嵌入样式映射、外部文件访问关闭，图像字节不读取。界面显示表格数量与未覆盖的图像、嵌套结构；嵌套表格仅展平内部文本。仍不恢复 Word 分页、原始排版或完整公式，上下标可见不代表数学语义已核验。

回答中的引用编号与本次实际来源集合核对。不存在的编号显示警告，不创建虚构来源；没有可识别编号也提示核对。编号匹配只说明模型使用了一个存在的来源标签，不保证这个来源能支持该结论，更不代表专家验证。

项目菜单支持当前版本对话与证据导出为 Markdown 或 JSON，包含问答时间、版本 ID、文件 SHA-256、检索策略与范围、追问主题和完整来源切片。导出时按字段清单读取已保存问答，不包含模型凭据、其他版本或未完成回答。源片段与当前解析逐字匹配的结果独立记录；未匹配与无法检查明确展示。编号仅在每条回答内部有效，历史来源不会被新检索编号覆盖。Markdown 中问答与原文使用文字代码块，避免将论文中的链接、HTML 或反引号变成可执行内容。

v19对话导出升级paper-audit-chat@2，复用exact-occurrence@2拒绝无偏移的重复引文及错误偏移，不移除原文末尾空白。保存时版本/解析身份与当前身份独立比较；已知不符停止确认来源，身份缺失保持未知，即使当前文字匹配也不证明生成时材料一致。原始问答及来源不改，Markdown显示状态，外部JSON读取程序需支持新格式。详见conversation-notes.md。

## 6. 评审工作流与多模态能力

现有科学评审按版本化生态学规则执行，覆盖科学质量检查与范围、伦理材料门槛。每项通过真实模型调用获得结构化候选，再校验逐字引文并进行独立模型复核。系统保留未完成、失败、待补材料及不可判定状态。

逐条规则将不同缺陷拆成独立问题，保存严重性理由、修复路径和复查条件。材料请求不作为科学扣分；重复缺陷按主项关联，不能把一个真正问题的证据缺失当成已经解决。得分显示已评范围与覆盖率，没有完整证据时不生成完整分数结论。

执行器 4.1.0 要求任务、全部检查和可计分覆盖完成，且所需视觉材料完整可读，才能显示暂定完成状态。部分引文失败时保留其他有效意见，报告继续显示需要补充材料；不得因为仍有一条有效意见而表示全部完成。旧执行器任务需新建评审，避免混合不同策略，旧报告保持冻结。

PDF 视觉审查将真实页图分批提供给支持 image_url 的模型，对图表区域定位、放大和复核，保留可读性与覆盖状态。现有自动测试覆盖超过 24 页的分批处理、失败批次重试、密集表格和无效区域拒绝。DOCX 视觉审查仍需另存 PDF；不支持扫描件 OCR 和精确公式恢复。

修订流程读取旧问题及新版证据，判断是否满足修复条件。移除原引文不自动标为解决，模型暂判也不会自动关闭作者的问题账本。历史报告和规则版本保持冻结。

该模块属于显式 AI 工作流，目前不具备通用自主规划 Agent、MCP 或 Function Calling 接口。这些能力可作为后续研究方向，不能用技术名称替代现有实现证据。

## 6.1. 证据工具和审查预算

本轮增加两个用户手动触发的证据工具。参考文献模块扫描明确书目标题后的原文，在附录或补充材料标题处停止；最多查询 20 个唯一 DOI，固定 Crossref/DataCite 精确接口、2 个在途请求、8 秒单请求与 45 秒批次截止。保存原条目、元数据、差异、失败、机构 URL 和时间，不猜 DOI，也不把未查到当成虚假。

CSV 模块接收最多 2 MiB、20000 条记录、100 列的 UTF-8 CSV，按列映射确定性复算全表及分组非加权均值、样本标准差、缺失与非法值，提示重复 ID，并与人工输入的论文均值和容差比较。逐字原文引用可定位；使用缩放 Welford、标准差分母 n−1，无法形成有限数值时明确标记。CSV 原文不持久化、不发给模型，保留指纹、算法、映射和统计快照。差异不等于造假，未执行显著性、独立性或因果检验。

科学审查新增累计调用次数与运行时间预算，失败和自动重试计次，渲染和等待计时，用户暂停时间排除。预算耗尽保存部分报告并显示覆盖缺口，提高预算后继续同一任务；历史报告冻结，预算变更留痕。新报告保存当时工具结果，网页可查看冻结摘要，三种报告导出包含独立附录，各工具 JSON 提供完整结构化记录。评审模型尚未消费工具结果，不改变科学评分；手动工具不是自主 Agent。

## 6.2. 主张与证据链

用户从规则提取的原文候选句或自行输入的主张出发，在当前版本检索最多 6 个片段、8000 字符上下文。候选与检索扫描限制为 2000 区块、120000 字符，并显式标记部分覆盖；原文候选不把参考文献条目当成论文自己的结论。未开启模型时仅显示相关片段，没有命中时不发起模型请求。

开启模型后，单次结构化请求判断支持、矛盾、上下文或不明确。服务器拒绝未知来源和非连续逐字引文，重新计算真实偏移；不把模型提供的 ID、路径或页码作为导航事实。通过引文校验只证明文字来源，关系判断仍标记待人工核对。

检索片段内引文重复时，模型须给出唯一连续上下文，或提供经服务器核对的片段内 UTF-16 quoteOffset，换算为原文位置后保存。错误或缺失位置不能作为已通过引文核验的关系。策略标识为 claim-evidence-bm25@2。

人工确认、否定及待核查说明以事件追加，保留模型原始判断。每版本保存最近 10 个证据链快照，每快照最多 20 条人工记录，按工作空间、版本和解析身份隔离。新报告冻结当时结果与记录，后续修改不覆盖历史。该模块不自动改变科学评分或关闭问题。

## 7. 前端工程、隐私与部署

TypeScript 定义消息、原文锚点与检索元数据契约；EvidenceSources 组件独立展示来源，复用现有 locate 导航。Markdown 经过 DOMPurify 清理，模型文字不会直接成为导航按钮或可执行脚本。手机布局能够在对话和原文间切换。

匿名 HttpOnly/SameSite Cookie 标识工作空间，项目、文件和任务访问在服务端隔离；写入接口校验同源来源。API Key 使用 AES-256-GCM 加密保存，公开配置接口不回传密钥，导出内容排除密钥。更换模型服务地址必须重新提供 Key，防止把旧凭据发送给新服务。

这些措施面向本机匿名使用。清除 Cookie 可能失去工作空间访问凭据，当前无账号恢复或跨设备同步；管理员可读取服务端数据，不能宣称端到端加密。公网多人服务需要在本机版本之外补齐登录、配额、容量和备份管理。

运行要求：Node.js 24.12+；npm ci 安装锁定依赖。开发执行 npm run dev 后访问 127.0.0.1:5173；生产执行 npm run build、npm start 后访问 127.0.0.1:3001。PORT、HOST、DATA_DIR 见 .env.example，默认本机监听。导出 PDF 及浏览器测试需要 Playwright Chromium 或受支持的 Chrome。

## 9. 创新点、应用价值与后续计划

应用创新是以证据为单位联结原文、对话、意见和修订，而不只返回一段文本。检索、评审覆盖和无法判断的原因成为可见交互内容；问题具有明确修复条件，支持跨版本追踪。

工程创新体现在工作流和证据约束组合：可复现的全文词法检索、固定来源标签、服务端原文导航、结构化分项校验、不可变报告快照和分批视觉覆盖。这里是本项目的组合设计，不宣称这些基础技术首次出现。
