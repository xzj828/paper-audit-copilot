# 分项目与版本的会话草稿

切换项目或论文版本时，问答输入分别留在各自位置；导航不自动发送或复制草稿。内存按项目ID和版本ID隔离，最多30个非空草稿，按最近编辑淘汰；每条最多4000个UTF-16代码单元。读取不会创建或重新排序记录。不写localStorage、sessionStorage、文件或服务端，刷新/关闭页面清除。不同标签页不共享，不能当作持久笔记或跨设备同步。

解析等待完成保持文字；关联的评审问题还要求相同解析ID、问题在当前版本仍存在，否则不附带旧问题。删除项目清除草稿，并拒绝迟到请求重新恢复。发送捕获原草稿位置；响应开始仅清除该位置未改的原文字，完成只清除仍相同的问题上下文；失败/停止仅在原位置为空时恢复。不清除另一项目的相同文字，不覆盖后续新输入。相同位置重写完全相同文字的意图无法区分；停止不是撤销服务端已完成记录。

两项浏览器控制实现前登记；初始表达式及等待条件错误单独保留，修正后有效旧实现2/2失败。真实上传两项目、两版本往返验证不同草稿、手机、刷新、浏览器存储未写和服务端版本快照不变；受控延迟响应验证另一项目相同文字不丢失、仅原项目保存一条回答。两项Node覆盖实际组合逻辑、解析/问题身份、容量、删除与延迟边界；目标8浏览器通过，最终生产构建250项Node与64项浏览器通过。有限开发控制不是专家准确率。范围、失败日志与实现指纹见chat-drafts-validation.json。
