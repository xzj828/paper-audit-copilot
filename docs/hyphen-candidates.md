# PDF 换行断词候选：保留原文与人工核对

在 PDF 的“搜索论文”中，默认按原有逐处字面/空格与换行兼容规则查找。勾选“查找 PDF 换行断词候选”后，可为 `microbiome` 找到原文 `micro-` 换行 `biome`。搜索列表标为“断词候选 · 请核对原文”，点击后阅读器继续提示“词义与拼写需人工核对”；逐字核对仅指原始引文和位置，不证明去掉连字符后的拼写或含义正确。

策略 pdf-hyphen-candidates@1 是独立的手动搜索扩展，原 source-occurrences@1 及其实现指纹保持。候选只允许原文 ASCII 连字符、可选 ASCII 空格和单次 LF/CRLF，两侧各至少两个原始 ASCII 字母；正则大小写折叠后再核对实际源字符。仅支持200个UTF-16字符以内的查询。纯字面或原有空白兼容匹配保持原标签，不重复标成候选。

候选与普通结果合并后按原文顺序最多显示60处；所有引文直接切取原始UTF-16范围，连字符、换行与空格全部保留。位置框仍使用原有逐字映射，可能覆盖相邻字。不会改写解析文本、原文件、批注、报告或检索索引；不影响BM25问答和模型评审。关闭开关或修改查询会清除当前定位，刷新或更换版本后默认关闭；DOCX不提供这一开关。

不跨页或区块，不越过TAB或空行，不处理软连字符、OCR、非ASCII断词、数字范围或跨页表格。不能判断一处连字符是排版断词还是真正复合词：例如 `tree-` 换行 `based` 也可成为候选，应由人保留连字符。不能恢复栏目语义或证明阅读顺序正确；遇到并列区仍须核对原页。未知候选不作为新的原文证据或科学结论。

实现前真实本地提交26d86c2登记18项开发者工程控制和3项原始PDF片段；材料SHA-256 dc86e354357292020748589ca7bb91478fa3a7a72a1d7ad7c654f8656dbe1a4a。固定预期未调整，全部实际结果、源切片、切片指纹、定位框和实现指纹见hyphen-candidate-results.json。控制包括普通断词、CRLF、多词、多次断词、正则字符、真正复合词的候选提示、普通匹配排除、大小写，以及空行、TAB、非ASCII连字符、数字、短边和非ASCII文字拒绝。另有Node覆盖重叠位置、数量限制、过长查询和Unicode大小写折叠边界。

真实材料沿用 Beule 与 Karlovsky（2021）PLOS ONE 原始20页论文，DOI 10.1371/journal.pone.0246919，CC BY 4.0，未修改源文件。作者、来源和原文件SHA-256保存在tests/fixtures/published-pdf/source.json。实现前用独立pypdf提取并查看原页1、5、11，分别登记 `environ-` 换行 `mental`、`normal-` 换行 `ized` 和 `PERMA-` 换行 `NOVA`。实际生产Worker解析后3/3片段均作为候选找到，并各映射两个原文文字块；默认搜索不返回这三条含连字符的切片（其他完整拼写的出现仍可找到）。这是固定来源定位检查，不是专家准确率、通用论文成功率或新的独立保留评价集。

另一份两页手写PDF仅用于开发控制，预先指定两行位置，并把跨页单词拆在不同页。Node验证实际Worker、严格原文偏移及两个框；浏览器真实上传，验证默认关闭、显式开启、候选与原文警示、关掉开关清除定位、390px缩放、刷新重置、修订上传为DOCX后不可开启，以及原PDF解析快照未改变。控制中的文字与结论不是专家标注。

## 复现

`npm run evaluate:hyphens -- --output 指定目录` 离线使用仓库中的获许可原文件，输出全部固定控制和3条真实来源检查；零外部模型请求。完整构建与回归命令仍为npm run check。真正复合词、复合布局、扫描件和跨页表格仍需人工核对，独立领域评测仍待真实专家与保留材料。
