# 6 分钟普通话演示脚本

录制要求：MP4、1920×1080 或更高分辨率、普通话讲解；总时长控制在 5–8 分钟。以下是录制提纲，不是已录制视频。演示用团队自有或许可公开的论文，遮蔽 API Key 与个人数据。

| 时间 | 画面与操作 | 讲解重点 |
| --- | --- | --- |
| 00:00–00:40 | 浏览器打开 Web 工作台，展示空首页和项目创建 | “这是学术审稿 Copilot。我们针对论文阅读、评审证据和修订记录分散的问题，构建可追溯的研究工作台。” |
| 00:40–01:20 | 上传 PDF/DOCX，显示真实解析进度、原文页和解析限制 | “文件经过去重和后台解析。PDF 保留页与文字坐标，Word 提供段落预览。无法提取的图像不会被当成已读取文本。” |
| 01:20–02:20 | 询问论文后部的具体方法，展示检索范围、流式回答和证据卡片，点击定位 | “以前只发送论文开头，长文档后部会遗漏。现在从全部已解析文本中检索，将有限片段送给模型，回答引用与原文可直接对应。” |
| 02:20–02:50 | 提问不存在的内容；如受控模型测试则展示无效引用警告并明确测试性质 | “没有找到证据时不会拿无关内容凑答案。编号匹配也不等于结论已经核验，我们把这个边界直接展示给用户。” |
| 02:50–04:00 | 配置已启用模型，选择生态学实证评审规则，启动评审，展示进度、独立问题、材料请求、失败重试 | “评审采用显式检查与独立复核工作流。材料缺失和科学缺陷分开记录，不因缺失材料就自动扣分。” |
| 04:00–04:50 | 上传修改稿，比较版本，展示同一问题的修复条件和语义复查 | “删掉一段文字并不自动代表解决问题。我们保留旧问题和旧报告，用新版证据检查是否满足修复条件。” |
| 04:50–05:30 | 打开报告、查看覆盖率并导出 Markdown/PDF/DOCX；切换手机宽度 | “报告保存版本、规则、证据和覆盖范围。论文、对话和问题可以联动定位，也支持窄屏阅读。” |
| 05:30–06:00 | 展示仓库结构、真实 Git 提交、测试结果和能力边界 | “本作品使用 Vue 3、TypeScript 和 Node SQLite，可按 README 复现。仍需真实领域专家校准；目前不支持扫描件 OCR，也不宣称自动替代同行评审。” |

建议提前准备一个已完成的真实模型任务用于展示结果，同时现场启动一个新任务展示调用和进度。不得把预先保存的结果描述为刚刚产生，也不要用加速画面伪称实时速度。

正式演示不需要让评委等待全部检查结束。长耗时评审的等待可通过画面切换说明，但保证关键流程可核查。录制前核对团队信息、比赛编号、模型服务费用、论文许可和最终文件时长。
