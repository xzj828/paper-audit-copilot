## 配置与材料

- 官方地址：`https://api.deepseek.com`；模型 ID：`deepseek-flash`；已启用图像输入。
- 官方模型列表实际返回 DeepSeek-V4.1-Flash；[发布说明](https://api-docs.deepseek.com/news/news260910/)说明该版本使用此 ID 并支持原生视觉。[Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)说明推理模式及输出额度。
- 两篇自制中文生态学文本：正确处理独立样地与土壤子样的局地试验；故意把每处理一个样地的100份土样当独立重复，并混淆碳储量与年通量、声称未测量的微生物机制的反例。材料见 `tests/ecology-cases.js`。
- 一张自制英文图表PDF：误差线在图注中为 SD，在方法句中为95% CI；图中有单位但故意没有纵轴数字刻度。原始PDF通过项目渲染器进入定位、裁剪、图文评审和第二轮模型复核。
- 文本直接注入解析结果，测试评审链路，不代表PDF正文解析验收；图表实验实际执行PDF渲染。所有材料均为合成，未上传用户论文，也没有专家金标准。

## 发现和已修复问题

1. **默认输出额度不足。** 旧请求仅给分析4096、复核2048 tokens；DeepSeek默认推理占用同一额度，部分响应 `finish_reason=length`，正文为空或JSON不完整。现在仅对官方DeepSeek V4系列设置至少16384 tokens，保留默认推理；通用兼容服务仍使用原预算。额度是上限，不等于每次实际消耗。
2. **截断处理不准确。** 现在明确拒收 `finish_reason=length`，不把它解释成“不支持Chat Completions”；超过处理上限的回答直接报错，不再用字符串截取制造损坏的JSON。
3. **图表证据编号混淆。** 实测模型把整页 `page-image-1` 当作图表区域编号。现在请求显式发送 `visualEvidenceTargets`，逐一对应图表、原文页与区域ID，并明确整页上下文图片编号不能作为区域锚点。严格输入归属校验保留，没有放宽成任意编号可通过。另明确最多6条证据，与后端Schema一致。
4. **运行版本与回归。** 执行器更新为2.1.0，旧任务不能与新执行器结果混用；新增预算、截断响应回归，补充HTTP集成的视觉目标映射断言。

## 科学判断观察及尚未修复的问题

- 正确设计样例的 E04/E06 判断为支持，没有把先按样地汇总的子样本当作伪重复；E07接受局地外推边界。
- 同一样例仍产生 E08 数据与代码获取的次要意见。它不是“无任何报告缺陷”的金标准；当前无法独立获得数据的声明是故意保留的。后续需要把材料请求、报告缺陷与科学有效性问题做结构化区分。
- 缺陷样例能识别伪重复、储量/通量混淆和未经测量的机制，但 E03 把多个独立缺陷合成一个结果，后续专项被整体标为重复。这证明粗粒度结果与去重机制需要重构，不能宣称逐项归属已验收。
- 图表修复后的任务完成三次真实请求：定位、评审、复核；返回有效页码、区域和引文，识别 SD/CI 矛盾及缺失刻度。区域包含图注与方法文字，定位较宽，仍需人工核对精度。
- 旧预算下基础版与适配版都有执行失败，且每个条件只有一次运行，不能从这次比较宣称Nature适配提高了准确率。

## 复现及记录边界

普通 `npm run check` 不消耗模型额度。付费实验须显式运行：

```sh
node scripts/live-ecology-evaluation.mjs --live --scheme=stxb-precheck@0.2.0-trial --output=data/experiments/another-text-run
node scripts/live-vision-evaluation.mjs --live --output=data/experiments/another-vision-run
```

脚本读取本机 `data/experiment-workspace.json` 指定空间的已加密模型配置。新机器需先在本机配置模型，并建立指向该空间的元数据；不能把Key写进脚本。输出目录应使用新路径，历史实验保留。

本次原始实验数据保存在被Git忽略的 `data/experiments/deepseek-2026-09-26-*`。文本有完整任务快照、汇总和API usage；视觉诊断额外保存合成材料的最终回答，不保存模型隐藏推理、请求鉴权头或Key。最初文本试验每次请求计时只到响应头，不能用它与后续完整响应耗时比较；按任务总耗时比较才有意义。

Token数依据服务商返回的usage。未核对账单，因此不把token数换算为“实付费用”。优先补齐计划见 [生态学缺口计划](ecology-gap-plan.md)。
