# 后台状态读取超时恢复

v34按当前页面项目快照限制一条进行中读取，阻止旧GET覆盖较新回答与报告。其当轮说明明确：GET一直未结束会持续占用该对象的键。v35只在poll内补充15秒读取阈值，不改变既有1秒尝试周期或全局api行为。

每次真正开始后台GET时建立AbortController及15000毫秒计时器，将signal交给现有api。计时覆盖fetch和response.json；项目数据读完即清计时器，finally再次安全清理并释放WeakSet键。中止或失败时catch保留页面，不弹出额外错误；仍有待处理任务时，原轮询可再次开始读取。应用返回数据前继续核对原对象、项目/版本/导航/设置/忙碌条件，并排除已中止signal。

控制在af73f87先提交：旧实现在15秒边界没有产生预期中止。修复后首轮目标3/4通过，新增控制在恢复后检查报告选择时失败：打开项目本来会清空选中报告，测试却沿用打开前选择。随功能提交将准备修正为重新打开后先选中已保存报告，再验证读取前后不变。没有更改报告选择实现或放宽保存断言，日志保留。最终5项目标与完整构建、265Node/82浏览器均通过。

新增控制真实保存离线检索回答和冻结工具报告，上传两个合成DOCX且Worker实际完成；只在浏览器初始GET将非当前版本标为待解析来驱动既有轮询。记录真实浏览器请求起点，受控时钟14999毫秒仍只1次读取且未中止，15000毫秒观察原生ERR_ABORTED，下一周期恢复GET，随后释放旧响应并检查标题、回答、选中报告和存储不回退；完成状态再推进16秒，没有继续查询。测试fetch包装只记录起点，原参数/返回值/signal均原样转发。没有调用外部模型，这不是模拟专家、真实Worker耗时或网络压力试验。

边界：15秒为浏览器计时调度阈值，后台节流与休眠可延迟执行，不能保证真实墙钟准点；AbortController取消客户端接收不等于取消服务器工作或计费。这里只覆盖poll的单次项目状态GET及正文；refreshList、手动打开项目、上传、模型问答和评审请求不使用此阈值。持续错误沿用原周期重试，没有指数退避或网络可用性保证。本轮未单独构造已收到响应头但正文挂起的控制，不把代码涵盖正文中止称为该场景已独立验证。数据库、导出格式、服务器任务不变。
