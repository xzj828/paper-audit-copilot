# 学术审稿 Copilot · 前端设计规范

版本：1.0  
更新日期：2026-11-07  
适用范围：整个系统的前端，包括工作台、文献库、模板与规范、设置、编辑器、弹窗、报告界面及移动端。

## 1. 设计目标

系统应呈现成熟、克制、清晰的专业研究工具体验。用户进入页面后，应立即看懂当前对象、任务状态和下一步操作，并能舒适地阅读论文与评审意见。

本次已确认的核心要求：

1. **字体、字号、行距和留白必须形成统一体系。** 消除临时拼装感，避免字小、拥挤、到处加粗或层级混乱。
2. **主动删除没有任务价值的文字。** 不用口号、重复提示、功能介绍和开发说明填充界面。
3. **规范覆盖全系统。** 新增页面、边缘状态、弹窗和手机界面都应保持相同的设计质量。
4. **让论文、证据和操作成为视觉重点。** 装饰、辅助说明与过程信息应退到合适的位置。

本文件是后续设计和实现的共同依据。当前样式文件提供实现基线；新组件、旧页面改造和验收均按本规范执行。文中“必须／不得”为约束，“默认／建议”为可根据真实内容调整的基线。

## 2. 信息与文案

### 2.1 每段文字必须有明确用途

保留一段界面文字前，至少回答以下一项：

- 它是否告诉用户正在处理什么？
- 它是否帮助用户选择或执行操作？
- 它是否解释当前状态、结果或失败原因？
- 它是否提供判断所需的证据？
- 它是否说明会改变用户决定的重要限制或后果？

如果都不能回答，默认删除。如果功能名称、按钮或布局已经表达清楚，不再补一句同义解释。

### 2.2 删除、收纳与保留的边界

| 信息类型 | 处理规则 | 示例 |
| --- | --- | --- |
| 品牌口号、情绪性宣传 | 删除 | “专注 · 严谨 · 更好的研究”“论文与研究，尽在掌握” |
| 重复操作引导 | 删除 | 已有“新建项目”按钮时，不再显示“新建项目，开始一次评审” |
| 模糊的欢迎语 | 用当前对象或任务名称替换 | “你的下一篇好论文”改为实际项目名，空项目使用“新建项目” |
| 常驻的技术说明 | 放到相关设置或详情 | 模型数据发送范围放到“模型服务”的折叠说明，不占据侧栏底部 |
| 工具实现过程 | 默认折叠 | 检索策略、绑定规则、详细核验记录 |
| 使用限制 | 在相关动作附近简短表达；完整解释按需展开 | 上传格式和大小、Word 预览限制 |
| 失败、异常、需处理状态 | 在影响用户操作的位置直接显示 | 解析失败、来源不匹配、模型不可用 |
| 论文原文、评审结论与证据 | 保留原意与完整访问能力 | 不为缩短卡片而改写、删除或弱化科学意见 |

“减少废话”不等于隐藏错误、删除证据，或让用户猜按钮的作用。影响结果可信度的异常不得默认藏在折叠区里。

### 2.3 文案写法

- 按钮使用具体动作：`上传论文`、`创建项目`、`保存更改`、`在原文中定位`、`导出 PDF`。
- 标题使用明确对象：`文献库`、`问题详情`、`模型服务`，避免泛化的欢迎语和宣传性副标题。
- 常规反馈用一句话说明结果；失败反馈说明原因及可执行的下一步。
- 不常驻显示用户无需理解的服务端、解析器、检索算法等实现细节。
- 术语在全系统一致。同一对象不要在不同页面随意称为“项目／任务／研究空间”。
- 视觉标签、可访问名称和实际动作应语义一致。
- 不因页面显得空而补文案，也不为追求简短而制造模糊表达。

### 2.4 默认展示层级

| 层级 | 内容 | 展示方式 |
| --- | --- | --- |
| 第一层 | 当前对象、核心结论、关键异常、主要操作 | 直接可见 |
| 第二层 | 判断依据、当前进度、必要条件 | 紧邻相关内容，保持简短 |
| 第三层 | 完整过程、配置细节、技术解释、历史记录 | 通过详情、折叠区、设置或记录页访问 |

## 3. 字体与排版

### 3.1 字体

UI 统一使用以下字体栈，通过 `--font-ui` 引用：

```css
--font-ui:
  'PingFang SC', 'Microsoft YaHei', 'Noto Sans CJK SC', 'Noto Sans SC',
  -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif;
```

- 中文和英文应保持视觉协调。不得在不同页面任意换字体。
- UI 不使用宋体、手写体或装饰字体。
- 论文正文、PDF 和正式报告内容可保留文档自身排版；周围工具栏、提示和按钮仍使用 UI 字体。
- 需检查实际渲染字体，不能仅凭 CSS 中写了字体名称就认为字体已生效。
- 不用全局放大、缩小或 `transform: scale()` 解决排版问题。

### 3.2 字号基线

| 用途 | 默认字号 | 建议字重 | 行高 | 实现基线 |
| --- | --- | --- | --- | --- |
| 页面主标题 | 26 px | 600 | 1.4–1.5 | `--font-title` |
| 面板、弹窗标题 | 20 px | 600 | 1.5–1.55 | `--font-heading` |
| 长文阅读 | 16 px | 400 | 1.8–1.95 | `--font-reading` |
| 主要正文、评审说明 | 15 px | 400 | 1.6–1.85 | `--font-body` |
| 导航、表单、按钮 | 14 px | 400–500 | 1.5–1.6 | `--font-small` |
| 次要元信息、时间、计数 | 12 px | 400 | 1.5–1.7 | `--font-caption` |

- 移动端页面标题可用 22 px，顶部项目标题可用 16 px；正文不因屏幕变窄而整体缩小。
- 12 px 只用于辅助信息，不能用作主要正文。正常操作界面不得用低于 12 px 的文字；文档缩略图不在此限制内。
- 局部标题可在既定层级之间选择 16–18 px，但不能每个组件都自创一套字号。
- 通过字号、字重、间距共同建立层级，避免所有文字都加粗。
- 连续正文使用正常字距；不通过大幅拉开中文字符间距制造“高级感”。

### 3.3 长内容

- 正文自然换行，不出现横向溢出。
- 列表名称和窄工具栏标签可省略，必须提供查看完整内容的方式。
- 核心结论、错误原因和待确认的操作后果不能只依赖省略号或悬停提示。
- 原文摘录可以展示摘要区域，但必须有清楚的完整来源入口。
- 移动端不得依赖 hover 才能获取必要信息。

## 4. 间距与视觉节奏

采用 4 px 为基础单位的间距体系，优先使用：`4 / 8 / 12 / 16 / 24 / 32 / 40 / 48`。

| 位置 | 默认间距 |
| --- | --- |
| 图标与文字 | 8 px |
| 标签与输入框 | 8 px |
| 同组控件 | 8–12 px |
| 列表项、普通卡片内边距 | 12–16 px |
| 桌面面板、弹窗内边距 | 24 px |
| 手机页面左右内边距 | 16 px |
| 表单字段组之间 | 20–24 px |
| 内容章节之间 | 24–32 px |
| 独立页面区块之间 | 32–48 px |

- 同类元素必须对齐。标题、正文、表单和操作区应共享可识别的对齐线。
- 先用间距建立分组，再决定是否需要背景、分割线或卡片。
- 不为了“丰富”而给每一段内容加卡片、描边和阴影。
- 同一任务内的信息紧凑，任务之间有明显间隔。
- 空白应帮助阅读和定位；不要通过堆文字填满空间，也不要让低价值空白把关键操作推到屏外。

## 5. 色彩、边框与主题

### 5.1 主题基线

| 语义 | 浅色 | 暖色 | 深色 |
| --- | --- | --- | --- |
| 正文 `--text` | `#24282F` | `#38352F` | `#E6E9EF` |
| 次要文字 `--muted` | `#66707E` | `#746C5F` | `#A4ADBA` |
| 内容表面 `--paper` | `#FFFFFF` | `#FFFDF7` | `#22272F` |
| 页面底色 `--surface` | `#F4F5F7` | `#F4F0E7` | `#1B2027` |
| 边框 `--border` | `#E4E7EC` | `#E5DECE` | `#373E49` |
| 链接／选中文字 `--blue` | `#2563EB` | `#2563EB` | `#8DB5FF` |
| 引文底色 `--quote-bg` | `#FFF8E8` | `#F9EFD8` | `#393322` |

- 蓝色用于主要动作、选中与链接；琥珀色用于引文和需要注意的信息；绿色用于明确成功状态；红色用于错误和破坏性动作。
- 状态不能仅靠颜色表达，需结合文字、图标或形状。
- 主按钮当前采用 `#2563EB` 底色和白字。不得将深色主题的浅蓝链接色直接套用到白字按钮背景。
- 组件优先引用语义变量，不到处硬编码浅色背景、灰字和白色边框。
- 新增语义色需统一定义，并同时检查三套主题。

### 5.2 表面与可读性

- 普通输入框与按钮默认圆角 8 px；弹窗默认 14 px；壳层圆角遵循现有布局组件。
- 阴影用于浮层和层级表达；普通内容区优先使用间距或细边框。
- 不使用大面积炫光、装饰渐变、夸张阴影和无任务作用的视觉特效。
- 项目验收目标：普通文字与背景对比度至少 4.5:1，大号文字及重要控件边界至少 3:1。辅助文字不能淡到影响阅读。
- 深色模式必须检查输入框、弹窗、选中态、引文、禁用态、滚动条和悬浮菜单，不能只更换页面背景。

## 6. 页面布局

### 6.1 工作台

- 项目名称放在全局标题区，避免挤在窄对话栏内；桌面标题区基线高度 72 px。
- 论文阅读区优先获得剩余空间。默认对话栏宽 320 px，问题面板宽 360 px，并允许合理调整。
- 需要同时阅读的区域保持独立滚动；操作区不得随长内容完全消失。
- 对话、论文、问题详情之间有清楚边界，避免多层嵌套卡片。
- 支持左右布局、上下布局、预览最大化和恢复；切换后不得丢失项目、版本或当前内容。
- 最大化预览应覆盖可用视口，不能继续受原网格列宽限制。

### 6.2 导航与侧栏

- 主导航保持稳定：新建项目、文献库、模板与规范、设置。
- 最近项目只展示可识别的项目名称及必要状态，不加入宣传段落。
- 当前采用可拖拽的侧栏抽屉。拖动过程中，前景内容整体平移，内部文字、表格与卡片不反复压缩重排。
- 导航打开状态用于选择入口；关闭后的任务状态必须保证核心操作可达。
- 侧栏拖拽、面板尺寸调整、文本选择、输入控件和垂直滚动必须互不抢占。
- 提供清楚的展开／收起按钮和键盘操作路径，不能要求用户必须发现隐藏手势。
- 侧边导航的悬停背景由整行容器承担，覆盖图标、标题和右侧操作区，不能只在文字按钮后形成一小块高亮。项目子聊天的缩进放在行内内容上，行背景仍与其他条目左右对齐；选中态同样作用于整行。此规则适用于主侧栏、管理分类、设置及模板编辑侧栏，保留各区域原有主题色和动效。

### 6.3 管理页面

- 文献库与模板页优先展示对象、搜索、筛选和主要动作。
- 页面只保留一个清楚的主标题，不叠加无作用的面包屑、欢迎语和介绍横幅。
- 列表、网格和缩略图视图共享搜索、筛选与选中语义。
- 设置按任务分组：工作台、评审、模型服务。数据管理页面及入口已按用户要求移除，不删除已有业务数据。实现细节放入相关分组。
- 重要操作有稳定位置；保存状态、未保存修改和失败状态应清楚。

## 7. 关键组件

| 组件 | 设计要求 |
| --- | --- |
| 按钮 | 一个任务区域通常只有一个主动作；次要动作使用次级样式；图标与文字对齐，避免一排同等强度的蓝按钮。 |
| 输入框 | 标签清楚，placeholder 只作补充；错误紧邻字段；长模型名、长文件名不得覆盖发送或保存按钮。 |
| 标签页 | 选中态明确；切换语义稳定；标签过多时允许局部横向滚动，不让整个页面溢出。 |
| 弹窗 | 明确标题、任务内容、取消与提交；长表单内部滚动，底部动作可达；不要重复介绍弹窗名称已表达的功能。 |
| 列表／表格 | 名称为主，元信息为辅；计数与状态格式一致；空状态、加载状态和筛选无结果需区分。 |
| 提示 | 在相关动作附近出现；短暂反馈及时消退；不能让 Toast 成为查看错误或关键状态的唯一途径。 |
| 图标 | 使用现有 Lucide 图标体系，统一尺寸与线条；常规 16–20 px；图标按钮具备可访问名称。 |
| 空状态 | 一个简洁标题，加一个合适的主要动作；必要时补一句条件说明，不堆功能卖点。 |

新增常规按钮高度默认 40 px，输入框默认至少 42 px；移动端主要触控目标建议至少 44 × 44 px。视觉小图标可通过透明内边距扩大点击区域。

### 7.1 下拉表单（2026-11-07 确认）

- 采用[已确认方案](design/dropdown-options-2026-11-07/simple/selected.png)：浅灰圆润触发框、轻阴影菜单、淡蓝选中项和右侧勾选；不添加搜索、分组、详情侧栏等额外层级。
- 按后续截图批注，评审设置不再常驻展示规则下方的版本号、试运行标签和人工复核提示；默认规则区块底部内边距从 56 px 收紧为 32 px。该调整只涉及此处展示。
- 下拉触发框高度至少 44 px、圆角 22 px；菜单圆角 16 px、选项圆角 12 px，选项最小高度 48 px。该组件的圆角按本节执行，其他表单控件保留既有基线。
- 三种主题统一复用语义色。长名称在触发框单行省略，展开后完整换行，箭头始终保留。只对已知内置规则名称提供简短展示名，存储值与规则内容不变。
- 菜单淡入／淡出与 4 px 位移为 160 ms，箭头同步旋转；悬停与选中背景柔和过渡。遵循系统减少动态效果设置。
- 所有单选下拉表单复用 `src/select.css` 和 `SelectContent`；模型菜单共享圆角、选中态和动效。保留原生标签、键盘选择、Esc 取消、禁用项、校验及数值绑定。
- 在支持 `appearance: base-select` 的桌面运行环境中启用完整菜单样式；其他浏览器保留可操作的原生菜单。不得为追求外观移除原生选择或校验能力。
- [实现与验收记录](design/dropdown-options-2026-11-07/implemented/QA.md)。

## 8. 对话、评审与证据

### 8.1 对话

- “对话”突出问答和有价值的评审结果；上传、解析、调用等完整过程在“记录”中查看。
- 处理进度使用简短且真实的状态，不能生成虚假的完成百分比。
- 生成时保持等待或流式反馈可见；不让证据详情把当前回答和停止操作挤出视口。
- 输入区保持稳定。评审配置、模型选择、附件等操作可用，但不能压过输入与发送。
- 消息引用和完整证据入口清楚；不要把一大段检索规则放在每条回答之前。

2026-11-09 对话页与原文搜索调整的实现、截图及回归范围见[验收记录](design/conversation-2026-11-09/QA.md)。复合搜索框由外层统一提供焦点边框；较长搜索结果独立滚动，输入与关闭操作保持可达。

同日按用户后续两张参考图调整：原文搜索采用浅灰胶囊外观，桌面40px高、手机44px高，默认无可见描边；单选下拉采用胶囊圆角、最小46px高。对话中的评审规则独占一行，稿件类型和输出方式并列，控件文字16px。模型选择沿用相同表面。参考与实现见[并排对照](design/conversation-controls-2026-11-09/comparison.png)，新参考优先于此前局部样式。

### 8.2 问题详情

默认顺序：问题级别 → 问题标题 → 原文位置 → 问题说明 → 原文依据 → 修改建议 → 必要核验细节。

- 首先展示选中的问题；全部问题、搜索与筛选通过独立入口展开。
- “在原文中定位”和“继续讨论”保持清楚、可达。
- 原文引用在颜色与排版上区别于系统说明。
- 核验详情、复查条件按需展开；异常证据状态直接提示。
- 阅读状态、核验状态、问题是否解决必须区分。不得把“已阅读”包装成“问题已解决”。

### 8.3 原文与报告

- 不改变用户论文内容，不为美观伪造页码、高亮位置、引文或证据结论。
- 系统提示使用 UI 样式，不能混入论文段落而让用户误认为原文。
- PDF 保持真实渲染与缩放；Word 结构化预览在适当位置解释其展示范围。
- 报告的可信度、覆盖范围、来源与版本信息应保留，专业内容可使用正式文档排版。
- 导出动作反映真实格式与内容；成功提示只能在实际操作完成后显示。

## 9. 响应式与交互

- 桌面、窄屏和手机应重新组织布局；不能只把桌面整体缩小。
- 当前布局分界参考：700 px 以下使用手机工作台；701–900 px 使用紧凑导航；901 px 以上支持桌面抽屉；问题详情在较窄工作区使用覆盖面板。
- 手机突出当前任务，通过切换查看对话与论文；不强行并排放入所有面板。
- 表格、目录和标签等确有需要的内容可在自身容器滚动，页面主体不得出现非预期横向滚动。
- 固定底部操作区需为正文留出足够空间；滚动到底后，最后一行内容必须可以完整查看。
- 保持键盘焦点可见，弹窗支持关闭并合理恢复焦点；开关、表单、菜单可通过键盘操作。
- 动效只表达状态与空间变化。一般过渡建议 150–250 ms，侧栏吸附可约 300 ms；尊重减少动态效果的系统偏好。
- 不在输入、阅读或拖动时加入无关动画，不用动画掩盖布局跳动。

## 10. 实现约束

- 通用颜色与排版优先维护在 [`src/design-system.css`](../src/design-system.css)。组件复用共享变量，避免复制一套相近但不一致的数值。
- 侧栏布局与拖动遵循 [`src/sidebar-motion.css`](../src/sidebar-motion.css)、[`src/useSidebarDrag.ts`](../src/useSidebarDrag.ts) 的现有结构；面板尺寸逻辑集中在 [`src/useLayout.ts`](../src/useLayout.ts)。
- 不用大量新增覆盖规则掩盖原因不明的样式冲突。修改前确认选择器、作用域与加载顺序，及时整理重复规则。
- 除明确的功能调整外，视觉改造保留数据、行为和已有能力；文案减量不能破坏可访问名称、错误恢复与证据访问。
- 对比设计稿时保留真实数据长度。可以调整容器和排版，不得伪造数据来使截图更好看。
- 新页面先确认信息优先级，再决定组件；不得默认生成欢迎横幅、统计卡片、功能卖点和装饰区块。

### 17.2 Codex 导航结构与实际功能（2026-11-09 后续确认）

- 以用户给出的“新聊天、项目、最近”参考为结构依据，延用原项目深色侧栏、字号、尺寸、圆角与动效。SVG 使用 Lucide 的 SquarePen、FolderOpen／FolderClosed、ChevronDown／ChevronRight、MoreHorizontal、Plus 等对应图标。

### 17.3 输入框模板级联菜单（2026-11-10 确认）

- 附件按钮右侧增加 Lucide Plus 图标按钮。按用户后续标注，点击只显示“评审规则”“报告模板”一级菜单；悬停分类才展开第二级实际条目，触控通过点击分类展开，键盘通过右方向键展开。每类可选一项，重新打开时重置为一级菜单。
- 加号按钮保持透明背景，悬停时图标变蓝；打开时加号平滑旋转45度，关闭时反向复原，过渡250ms。用户明确要求体现旋转过程，本控件在减少动态效果模式中采用160ms短过渡，避免被全局规则压缩为瞬时切换。菜单保留Esc及点击外部关闭。
- 复用共享菜单圆角、浮层阴影、UI字体和主题变量，操作文字14px，条目最小44px。第二级内容区高度上限240px，视口不足时进一步收缩；条目增多只在第二级内部滚动，不撑高浮层。手机保留两级结构与可读字号，分类名称单行，长条目换行；浮层根据视口空间向上或向下展开。
- 按用户后续决定，取消输入区域固定高度。选中项在顶部显示可移除标签，多个标签可换行撑开；正文在标签下方输入，保留3行基础高度，随实际显示行数自动增高，最多10行（包含自动换行），超过后仅正文内部滚动。删除文字、切换聊天、恢复草稿和调整宽度时重新计算高度。下方还有未显示文字时，正文底部出现20px轻微模糊渐隐；滚到末尾或内容不足10行时消失，效果不阻挡鼠标操作。选择按聊天保存，随消息发送并保留名称记录；仅选择不自动发消息或启动评审。加载、空列表、失败和重试状态直接显示。服务端核对真实条目，失效选项明确报错，不能静默换成其他模板。
- 用户尚未指定规则或报告模板时，智能体获得当前账号可用的真实条目清单；准备评审或用户请求选择时，先列出未指定类别供用户选择，不自行套用首项。已在本轮或历史中明确选择的类别不重复询问。普通聊天、一般写作和恢复既有评审不强制选择。
- 按本次之前的用户纠正，主导航不再显示“新建项目”，项目分组加号继续提供创建入口；侧栏展开仍允许前景内容被视口裁切，不增加防遮挡留白。

### 17.4 评审预览操作精简（2026-11-10 确认）

### 17.5 阅读区选稿与正式报告方向（2026-11-10 后续确认）
