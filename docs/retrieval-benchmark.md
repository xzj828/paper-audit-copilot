# 检索可靠性固定合成回归评测

本评测复用实际 `server/retrieval.js`，只测本地词法检索、原文切片、版本身份和预算边界。不连接网络，不调用收费模型，不上传论文。固定材料及期望见 `tests/fixtures/retrieval-benchmark.json`；执行与报告脚本为 `scripts/evaluate-retrieval.mjs`。

所有材料均为开发者自编合成文本，预设标签明确命名为 **developer-authored expected labels**。它们不是领域专家金标准，也不是真实论文准确率。词法检索取到正确区块，不证明随后模型的结论被该证据支持；支持、反驳、无法判定等语义关系不属于本评测指标。

## 复现

本轮完整输出随仓库保存为[逐项 Markdown 记录](retrieval-benchmark-results.md)和[结构化 JSON](retrieval-benchmark-results.json)，包含两个实际失败案例、原文切片及本机耗时。重新执行会产生新的时间与耗时记录，材料指纹和固定预设保持可比较。

使用 README 指定的 Node.js 环境。无需配置模型密钥或模型地址：

```sh
node scripts/evaluate-retrieval.mjs
# 默认仅输出结果，不写入仓库或当前目录。

node scripts/evaluate-retrieval.mjs --output test-results/retrieval-benchmark
# 明确指定目录后，保存 retrieval-benchmark.json 与 retrieval-benchmark.md。

node --test tests/retrieval-benchmark.test.js
```

也可使用仓库命令 `npm run evaluate:retrieval`。`--fixture <JSON路径>` 可加载同一格式的独立固定材料；`--top-k <1至8>` 可检查不同片段上限。正式本轮基准为默认 **k=8、上下文最多12000字符**，与实际问答默认值一致。降低 k 后可能不能同时取到两端的概览证据，门槛失败会如实报告；不能把改变参数前后的百分比直接当作同条件比较。

默认输出包含语料哈希、检索策略、Node 版本、运行平台、指标及失败 ID。指定输出目录的 JSON 保存每个问题、预设区块、真实返回的完整原文切片、页/段/偏移、继承问题、范围说明和检查结果；Markdown 提供指标表、完整逐例记录和引文。输出不是模型生成报告。

## 材料与预设政策

固定集有 **18 个合成版本、38 个用例**，覆盖：

| 类别           | 固定检查                                                                                            |
| -------------- | --------------------------------------------------------------------------------------------------- |
| 中英文有限词表 | 中文样本量/方法/结果/局限性查询英文文本；英文 data 查询中文数据段                                   |
| 科学词与数字   | 独立样地、混合模型、储量与通量、312、0.031、kg、数字相连汉字“第2组”、单字母 p                       |
| 长文           | 背景超过24000字符后才出现的具体方法；期望必须含论文后部的真实短句                                   |
| 原文保真       | 续文、全角字符、换行和双空格、组合重音字符；匹配归一化不改写引用                                    |
| 无命中与版本   | 无关词、空文本、主题明确的非概览问题；旧版冰川文字不能进入当前栎树花粉版本，两个版本故意共享区块 ID |
| 概览与追问     | 概览两端抽样；短追问继承本版用户主题、连续追问、三条窗口过期、忽略助手主张、新问题不继承旧主题      |
| 选中意见       | 真实原文锚点可优先；编造的意见引文不能成为证据                                                      |
| 保留的能力缺口 | 中文光合作用→英文 Photosynthesis、中文生境破碎化→英文 Habitat fragmentation，当前有限词表没有覆盖   |

36 项 `contract` 用例是当前回归约定，要求全部满足固定预设。另有2项预先标记的 `exploratory` 用例，表达未覆盖的跨语言检索目标；失败进入总表和总指标，但不冒充当前能力承诺。不能在一次失败后临时把用例改成 exploratory 来让门槛通过；新增或更改材料、预设、分组均会改变语料哈希，必须保留差异并解释原因。

长文用固定 `repeat.text` 与 `repeat.count` 展开。哈希采用展开后的材料与全部预设期望，将对象键排序后计算 SHA-256；不包含耗时和生成时间。改变空格、原文、标签或历史发现会改变哈希，改变 JSON 缩进或对象键次序不会改变哈希。

## 指标含义与门槛

- **预设证据召回@k**：所有有目标的用例里，返回的有效原文切片命中的预设区块数 / 预设区块总数。有原文短句约束时，还须至少一个该区块的片段含对应短句。区块 ID 去重；不把返回很多片段当作高质量，也不估计全领域召回率。
- **无命中分类**：以固定 `expectedNoHit` 预设为标准。精确率为正确无命中数 / 实际无命中数；召回率为正确无命中数 / 预设无命中数。分别报告错误拒取与意外匹配计数。分母为零时为 null，不能填成100%。这些结果不证明全文、图像或附件不存在材料，也不是模型拒答率。
- **原文切片有效率**：检查每条引文的区块属于当前版本，字符偏移为非负整数，按原文该偏移切片逐字等于保存引文。分母是实际返回的片段数；没有片段时为 null。
- **版本检查**：检查返回版本/解析 ID，并检查不属于本版的引文是否能在显式排除的其他版本找到。跨版本引文计数与身份不符计数分别展示；共享区块 ID 不足以通过检查。这里不取代服务器真实空间权限和接口隔离测试。
- **预算检查**：实际片段数不得超过本次上限，上下文和记录的字符数不得超过本次预算。
- **耗时 p50/p95**：每例在当前机器单次测量本地检索，使用 nearest-rank：排序后的第 `ceil(n×q)` 项。包含版本拷贝与检索；不包含材料文件读取、网络、模型生成或用户等待。长短材料混合，因此不是公网服务 SLA、模型端到端速度或付费成本。

所有 cohort 的原文、身份、版本和预算完整性检查均须通过，否则退出状态为1，标记 `integrity_failed`。contract 预设有一项不满足也退出1，标记 `contract_failed`。只有探索性召回缺口时标记 `contract_passed_with_exploratory_gaps`，命令退出0，但完整保留失败。门槛是工程回归条件，不能解释为专家认可或获奖保证。

## 本轮实际观测（2026-10-07）

本轮先对两个边界做独立探针：`bm25-lexical@1` 在原文已有“第2组…”时查询“第2组”返回 no_match，在原文已有 `p = 0.03` 时仅查询 p 也返回 no_match。数字打断汉字连续段，以及单字母过滤导致漏取。仓库随后升级到 `bm25-lexical@2`，保留原文切片与已有停用词，并修复数字相连标签和限定科学符号；这两项现在命中。fixture 保存这两个真实初始观测，未声称已跑过整份 v1 基准。

| 全部固定用例          | 36/38    | 27/29，93.10%  | 10/12，83.33% | 10/10，100%        | 36/36有效    | 0          |

本次语料 SHA-256：`844a9e8e20e88a3fe739a0d4baf98d15d21dd5742fdef094ff373a40a3442d6e`。耗时属于本机实测，每次 JSON/Markdown 记录自己的 p50/p95；不把一次测量写成稳定性能承诺。以上百分比只能连同合成材料、全部失败和分母一起展示，不能选取 contract 的100%宣传为真实论文准确率。

仍未覆盖通用跨语言术语与语义近义检索。未命中的两项不是论文内容不存在，而是当前有限词表能力不足；未来若引入更多术语、向量或重排，需要保持这批固定材料、另外增加独立材料，并比较检索时延与误匹配，不能只为这两个词添加映射就宣称通用语义能力。

## 测试与下一步验证

新增测试验证：错误但来源有效的预设能被判失败；不存在的预设与编造引文在评测前拒绝；语料哈希稳定且对内容改变敏感；偏移错位不能获得有效召回；旧版同区块 ID 的引文被识别；空分母保持 null；无关首页回退会产生错误；缩小 k 会暴露概览后部遗漏；CLI 默认不写文件，显式输出保存完整记录；原文标记在 Markdown 中只作为文字保留。

真实效果验收仍待获准使用的论文与独立专家标注。应另外建立未用于开发的保留集，预先定义相关证据范围，按研究类型分组，并盲评问题准确性、漏检、证据定位、严重性和可执行性。专家判断与真实模型输出要分别保存，记录模型与规则版本、来源文件指纹及调用成本。不能用这个固定合成检索集替代该验收，也不能用另一次模型调用冒充专家金标准。
