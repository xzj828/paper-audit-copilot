# 提问与解析就绪

提问之前必须有目标版本，状态为ready，并具有解析对象。解析中、解析失败及旧ready记录缺少解析对象时，接口返回409 JSON，即使请求Accept为text/event-stream也不会先建立SSE响应。拒绝在检索、模型调用、消息锁和持久化之前发生，错误明确说明问题未保存。无效版本或消息长度错误仍保留原400行为。

页面禁用发送按钮，Enter处理函数也检查就绪条件；解析中可以编辑问题草稿，就绪后手动发送。不会自动发送、排队或重写已有记录。失败时提示重试解析。存在解析对象但没有可检索文字仍属于解析覆盖/检索问题，不据此宣称全文没有相关内容。

一项API软件控制使用真实服务及临时SQLite构造parsing、failed、ready无解析三种状态，分别发送JSON/SSE六次请求，检查409、完整版本不变和本机模型零调用；恢复ready并填入固定解析后，本机模型回调一次，问题与带正确parseId的回答各保存一次。材料是开发者构造，不是用户迁移或专家标注。

一项浏览器实际创建项目并上传合成DOCX，仅控制GET响应延长页面等待状态；原Worker正常解析。验证手机、草稿保留、Enter零消息请求、释放后手动发送及刷新仅一条回答。该控制验证前端就绪行为，不代表真实Worker耗时；接口拒绝有独立状态测试。

目标及完整检查首轮通过：生产构建、243项Node、56项浏览器。真实领域专家校准与全文goldIssues尚未完成，有限软件测试不等于专家准确率。实现与日志指纹见chat-readiness-validation.json。
