# 整套复查的清单身份与代码指纹

运行`npm run evaluate:pdf-suite`，或使用`-- --output /path/to/results`保存完整JSON。v48增加字段，schema继续为published-pdf-suite@1；旧字段、逐篇分母、固定顺序和失败非零退出规则不变。

- cases中的caseIndex从1开始，表示本次登记顺序；manifest仍是短文件名，manifestPath记录本次解析后的绝对路径。即使清单JSON损坏、Schema不合法或文件缺失，也可区分不同目录中的同名清单。
- 整套implementation保存scripts/evaluate-pdf-suite.mjs及scripts/evaluate-pdf.mjs的SHA-256，在逐案运行前读取。成功单篇的既有implementation增加server/retrieval-phrases.js，使v47显式短语规则也有指纹。
- 成功单篇仍保留实际读取的manifestSHA256、源PDF SHA-256、来源/许可声明及既有检查。错误案保留错误，不因有绝对路径就补造未获得的源字节指纹。

绝对路径是本机排障线索，可能含用户名/目录，不能当作跨电脑一致身份；跨电脑核对材料应以成功单篇实际内容指纹为准。路径不解析symlink别名为独立论文，也不认证清单内容、材料许可或来源。代码指纹只覆盖列出的文件；不是签名、完整依赖/运行环境证明或防篡改认证。复查期间应保持文件不变；这些记录不是对并发修改的原子快照。
