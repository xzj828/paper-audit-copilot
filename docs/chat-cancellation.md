# 停止回答与保存状态

回答生成时，原发送位置显示“停止回答”。停止请求调用AbortController，关闭浏览器接收，并通过既有服务端链路向模型请求传递中止信号。等待请求清理后恢复手动发送，用户可核对后重试；不自动发送或自动重试。当前不同新草稿不覆盖，输入为空时恢复原问题。

临时部分回答保留于当前页面，提示“若服务端已完成，记录仍可能保留，请刷新核对后重试”。临时内容不写入数据库，不保证刷新后保留。停止接收不是撤销：若服务器已经保存、完成确认仍在传输，正式问答保留并正常导出。若中止在完成前生效，既有服务器检查不保存未完成问答并释放消息锁。不能据此保证外部服务停止计算、停止计费或覆盖所有网络竞态。

停止后的导出提示以服务端已保存记录为准，不把临时文字当作正式回答。取消状态只存在于前端待完成消息，不新增数据库字段、不迁移历史对话，JSON格式不变。普通失败仍沿用原错误流程。

一项真实API控制实际上传合成DOCX，以本机模型输出部分SSE，中止后验证provider连接关闭、完整版本不变、锁释放及重试仅保存一次。测试首次错误地要求下一次读取立即报错，实际已有解码帧可以继续被读出；修正缓冲读取控制，产品服务器/模型/SSE模块未改。

两项浏览器分别验证手机部分流停止、草稿、空导出、重试与刷新；以及服务器真实保存后仅延迟浏览器确认，停止后正式记录/导出不改。仅第一项在原界面运行并因没有停止按钮失败；控制在35bfc90登记后实现，第二项完成边界控制随后补充。每个控制使用本机模型回调，没有外部模型调用或专家评测。

最终完整生产构建、246项Node、60项浏览器通过。既有流式等待测试仍验证原输出，发送禁用的旧断言同步为发送入口不存在、停止可用。材料、失败与实现指纹见chat-cancellation-validation.json。
