# 对话研究笔记：追问与证据导出

## 使用

1. 新建项目、上传 PDF/DOCX，等待解析完成。
2. 使用原文术语提问，并查看回答下方的证据卡片。
3. 输入“为什么？”“请再详细解释”“这个结果可靠吗”等明确的简短追问。系统重新检索当前版本原文，证据卡片显示沿用的问题。没有明确主题时会说明证据不足；输入新主题则执行新的检索。
4. 点击项目右上角“项目操作 → 导出对话与证据”。选择 Markdown 笔记用于阅读，或 JSON 记录用于程序核查。

导出针对当前版本，保留已经保存的问题与回答。生成中的回答不会被当成已完成记录导出。导出窗口可在桌面或手机使用；实际下载来自后端已保存数据。

采用 [有限术语映射](retrieval-terminology.md) 时，证据卡片显示匹配的术语与另一个语言名称。导出保存每条回答的 `terminologyVersion` 与 `termMappings`；短追问继承原问题后重新检索，仍记录当次映射。旧记录没有这些字段时不补写，不把词法映射称为模型关系判断。

## 记录内容

- 项目与版本 ID、原始文件名、文件 SHA-256、当前解析 ID、导出时间。
- 每条问题或回答的 ID、角色、保存时间与完整文字。
- 检索策略、检索版本和解析 ID、片段数、上下文字符数与范围说明。
- 追问沿用的用户问题 ID 与实际检索查询。
- 每条回答对应的来源编号、完整原文切片、元素、页/段落、偏移及引用状态。
- 引用警告及导出时的文字归属检查结果。

JSON 导出格式升级为 `paper-audit-chat@2`，原有字段保留；旧下载文件不改写，读取格式版本的外部程序需要支持 @2 及新增状态。`validation` 记录原文校验策略 `exact-occurrence@2` 与身份策略 `saved-retrieval-identity@1`。历史问答不做数据库迁移，也不补造旧记录的身份。

每条有检索或来源的问答新增 `sourceBinding`：保存时/当前的版本 ID、解析 ID，以及 `matched`（两组身份都存在且一致）、`mismatch`（已知身份不符）、`unavailable`（缺少身份而无法确认）。这是已保存字段之间的比较，不是签名、身份认证或生成时文件字节的独立证明。文件 SHA-256 仍属于导出标题中的当前版本，不冒充旧记录未保存的文件指纹。

| sourceMatch | 含义 |
| --- | --- |
| exact_match | 与当前解析原文精确匹配，且明确偏移有效；无偏移时只能有唯一出现位置 |
| ambiguous | 重复引文缺少明确偏移，包括相互重叠的出现位置；未确认位置 |
| not_found | 引文、明确偏移或已记录的 PDF 物理页不匹配；不猜另一位置 |
| identity_mismatch | 保存的版本或解析身份不符，停止确认该来源，即使当前文本有相同句子 |
| unavailable | 缺少当前解析，无法检查 |

来源新增 `matchScope: current_parse_text_only`。缺少旧检索身份时，唯一原文仍可报告当前文字匹配，同时 `sourceBinding` 必须为 unavailable；不能把二者合并成“生成时材料已核验”。Markdown 明确显示材料身份及文字检查范围。文字按与阅读器相同的精确出现规则核对，不移除原文末尾空白、不将非法偏移退回首个命中。若解析区块与锚点均记录物理页，也要求页码一致。

证据编号在每条回答内重新编号：两条回答各自的 R1 可以指向不同片段，不能把编号当成整篇论文的全局引用。导出完整原文，不只包含卡片的短摘录。Markdown 的用户文字与原文置于长度足够的代码块中，保留嵌入反引号、HTML 与链接为普通文字。

## 范围与验证

追问主题查找只读取当前版本最近三条用户问题，采用明确的中文短句匹配。它不使用助手生成的事实扩充查询，不跨版本或跨项目继承主题，不是通用语义意图识别。原文同义词漏检仍可能发生，查询为空不会调用模型。

导出只读取当前空间下指定项目的确切版本，不因错误版本 ID 回退到活动版本。字段按清单选择，不导出模型配置、加密凭据、其他版本、事件进度或正式评审报告。用户在消息中自行输入的文字原样保留，因此分享前应自行核对研究资料。

文字匹配检查证明片段的文字归属，不证明回答正确、模型推断成立或已由专家确认。Markdown/JSON 是研究记录，不是正式评审结论。

本轮测试采用合成控制论文与受控模型服务，覆盖追问主题、空命中、新主题不继承、工作空间隔离、明确版本选择、原文完整性、未知引用提示、桌面实际下载与手机端实际下载。专业模型质量与专家准确率仍需另行验证。


## v19 控制记录

四项新增 Node 软件契约覆盖重复/重叠引文、明确第二位置、负数/小数/字符串/不安全整数/null偏移、不同版本及解析但相同句子、缺少旧身份、错误物理页、尾部空白、换行不归一化和Markdown状态说明。旧实现四项全部失败；首次修复复跑8/9通过，余项为测试把JSON省略的undefined属性当成保留字段，修正测试构造器后9/9通过。

新增浏览器从空空间真实上传两个含相同样本量句子的DOCX版本，各自使用本地检索问答并实际下载。验证版本ID、解析ID和文件指纹不同、两份保存身份均与本版本一致、第二版本手机JSON/Markdown下载，以及第一版本完整记录和全部版本对象不变。这里没有伪造数据库中的旧身份；旧身份不符/缺失情形由明确的Node控制覆盖，不称为真实用户迁移验证、模型质量或专家准确率。全量检查及指纹见 chat-export-integrity-validation.json。

## 页面中的来源身份

v20为已保存回答及正在生成的回答同步展示来源版本/解析身份。身份不符停用卡片定位并提示在当前版本重新提问；缺少身份保留未知状态及当前原文尝试定位。身份一致只比较记录ID，不验证历史文件字节、文字位置或回答结论。与paper-audit-chat@2的身份判断使用相同契约，49组有限身份组合通过对照测试；不是身份认证。详见source-binding-status.md。

## 提问的解析前提

v21要求目标版本ready且具有解析对象；未就绪时JSON/SSE请求均409 JSON，问题未保存，页面保留草稿并要求就绪后手动发送。存在解析对象但没有文字仍走原有无命中范围提示，不能等同全文没有证据。详情见chat-readiness.md。

## 英文追问策略

v22的检索元数据新增可选followUpPolicy=bounded-follow-up@1，JSON仍为paper-audit-chat@2，Markdown明确列出策略。旧记录不补造该字段。有限英文短追问可沿用当前版本最近三次用户问题中的明确主题；带新主题的完整问题独立检索。详见english-followups.md。

## 停止接收与导出

v23生成期间可停止回答。临时部分文字保留于当前页面，未持久化的临时回答不导出，刷新会丢失；若服务端已在中止前完成，正式记录仍可导出。停止提示要求刷新核对，不声称撤销保存。详见chat-cancellation.md。

## 页面与导出共用的原文状态

v24把已有导出检查提取到shared/source-match.js，页面显示同样的sourceMatch状态；JSON仍paper-audit-chat@2，matchScope仍current_parse_text_only。文字/位置/页码已知不匹配或重复歧义时停用定位，解析缺失保持未知且身份没有不符时允许人工尝试。当前文字一致不证明生成时材料身份或结论正确。详见source-match.md。
